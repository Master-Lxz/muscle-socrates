# 动作视频管线规范（教学归纳）

## 触发与别名

用户提到具体训练动作（中英文/俗称都算）：深蹲/squat、卧推/bench press、硬拉/deadlift、
划船/row、引体向上/pull-up、俯卧撑、推举/press、弯举/curl、臀推/hip thrust、弓步/lunge…。
"怎么练/标准是什么/哪里容易错/哪个UP主教得好"都走本管线。

## UP主白名单

- 白名单UP的结果排最前；但**不排他**——白名单没覆盖的动作或优质内容照常收录，输出标注是否白名单。

## B站流程（主力，纯 API）

1. **登录检查**：`credentials/bilibili.json` 不存在 → 先跑 `scripts/bilibili_login.py`，
   让用户用B站APP扫码（AI字幕必需登录态；未登录搜索与元数据仍可用，仅字幕缺失）。
2. **检索**：`python scripts/bilibili_search.py "<动作名> 教学" --limit 20`；
   可再跑一次 `"<动作名> 教程"` 合并去重。
3. **重排**：白名单UP置顶 → 按播放量与弹幕/收藏活跃度 → 剔除明显低质
   （合集切片、纯混剪、时长 <3 分钟、无字幕且弹幕极少）。
4. **选 3–5 个**（白名单有结果则至少含 1 个），逐个
   `python scripts/bilibili_fetch.py BVxxx --out 临时素材包.json`。
5. **逐视频归纳**：
   - **字幕 = 教学文字稿**：提炼 setup/站位、下放与发力轨迹、呼吸节奏、次数组数、常见错误。
   - **弹幕 30s 爆点 = 观众反复困惑或拍案处**：爆点对应时间点附近的讲解是关键段，引用带时间戳（视频名 mm:ss）。
   - **高赞评论 = 集体纠错与补充**：用于修订要点；UP主自己的回复权重大。
6. **跨视频共识**：≥2 个视频都讲的要点 = 共识；只有一家讲且与文献冲突 = 存疑标注。

## 抖音流程

见 `references/douyin.md`（浏览器通用方案，不绑定特定浏览器工具）。
抖音 AI 总结是 ASR 直出，**术语常转错**（"髋关节"→"宽关节"之类），归纳时做常识性校对，
拿不准就不写；评论用来纠错。输出时注明"由 AI 总结+评论归纳，建议观看原片"。

## 与文献互校（动作条目必做）

动作问题同时跑文献管线快答档（检索 `<动作> biomechanics / injury / electromyography`），
产出"研究怎么说"（1–3 句 + 1–2 条已验证引用）。

冲突判定只有三种，写进条目"研究 vs 博主"表：

| 判定 | 含义 |
|---|---|
| 一致 | 博主做法与文献同向 |
| 博主经验 | 文献未定论，博主说法合理但非循证强结论 |
| 冲突 | 文献明确反对该做法，回答中必须提醒 |

## 输出格式（对话内回答）

```markdown
## 深蹲怎么练（依据 {N} 个视频 + 文献，检索于 YYYY-MM-DD）

**研究怎么说**：…（1–3 句，附 1–2 条已验证引用）

**博主共识**（凯圣王、谭成义 等）：
- 要点…（视频名 mm:ss）
- …

**观众最常踩的坑**（弹幕爆点 + 高赞评论）：…

**研究 vs 博主**：{一致/博主经验/冲突}——冲突时用小表展开

**推荐视频**：
1. 《标题》 凯圣王 · B站 · https://www.bilibili.com/video/BVxxx （播放 xx，检索于 YYYY-MM-DD）
2. 《标题》 某UP · 抖音 · https://www.douyin.com/video/xxx （检索于 YYYY-MM-DD，AI总结归纳）
```

## 沉淀

结果写 `wiki/{动作名}.md`（用 `wiki/_动作条目模板.md`）。视频行必含检索日期与状态
（有效 / 已失效（最后确认日期））。命中 >90 天的旧条目 → 建议重跑管线。
